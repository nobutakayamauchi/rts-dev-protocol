RTS Development Kernel v1

RTSを含む全開発を、AIやソフトを交換可能な形で安全・省資源・再開可能にする開発基盤。

DERIVED / NON-AUTHORITATIVE。RTSの正本、署名済み履歴、FREEZER、承認、権限を変更しません。

二本柱構造契約保護RTS展開

二つの基礎コア

RTS Trust Core判断、権限、証拠、遷移、checkpoint、完全性、再構成。
RTS Development Kernel開発憲法、work/state/tests/evidence、adapter、移行、保護クラス。
開発時：RTSはKernelを利用できる。
運用・再構成時：RTSはKernel、RTS-AGE、AI、adapter、HTMLなしで成立する。

交換規則

交換しても目的、最低成功、証拠基準、保護クラス、権限、RTS履歴は変えない。

リポジトリ保護クラス

順序クラス基本境界
1SANDBOX範囲内pilot。自動merge不可。
2COMPONENTtask branch、人間review。
3PRODUCT隔離branch、merge/release承認。
4RUNTIMEfail-closed、実機、rollback。
5GOVERNANCE原則提案・検証のみ。
6TRUST_CORE隔離提案、最低二段階承認、自動merge絶対不可。

RTS

  • RTSはTRUST_CORE。
  • Kernelを丸ごとコピーせず、開発時の薄いRepository Adapterのみ。
  • 固定base commit、read-only/fail-closed試験、rollbackを先に要求。
  • 署名済み履歴とcheckpointのbyte不変確認を要求。
  • Kernel承認やテスト成功はRTS承認を意味しない。
  • RTS Stage 2完了と別の人間Gate AまでAdapter提案はBLOCKED。

安全な展開

  1. Kernel Draftの整合性検証。
  2. SANDBOXへ薄いAdapter。
  3. 強制中断し、別AI・別chatでSTATEから復元。
  4. 別AI/tool Adapterで互換試験。
  5. 一クラスずつ展開。
  6. RTSは最後にStage 2と二段階承認を通す。
